`6ac62b01d7d8af3ab23fd2239728a791704a3f09`, gz-fuel-tools 12.0.0-pre2.

Fresh LLVM profiles were generated by the complete Rust test run with
`-C instrument-coverage`; matching llvm-profdata/llvm-cov exported LCOV for every
produced test and CLI executable. Both exported FFI symbols retain their production
names; test builds use distinct Rust symbol names to prevent cross-binary LLVM

Only explicit cfg(test) modules and their declared source files are excluded from
Rust production metrics. All production Rust source files must appear in the
report. GCC/gcov instruments every C++ facade source at O0; the coverage checker
enumerates gcno files so an unexecuted source cannot disappear from the denominator.
Each language independently must exceed 95%, strictly.

Raw reports are in `coverage/summary.txt`, `coverage/lcov.info`, and
`coverage/cpp-summary.txt`. Reproduce the gates with:


## Independent review and installation

Separate agents reviewed source compatibility, issue scope, IO/cache behavior,
typed client behavior, FFI boundaries, test integrity, coverage collection and
packaging. Findings and corrections are recorded in REVIEW.md and WORKLOG.md.

Independent production builds with BUILD_TESTING=OFF installed successfully without
an upstream Fuel source checkout. Fresh external consumers found the versionless
package and requested version 12, compiled the umbrella header with a version-macro
static_assert, linked and ran with the replacement library. Package relocation and
lib, lib64 and multiarch library directories were checked. pkg-config resolves the
relocated paths. The existing gz-tools program invokes the installed Rust CLI
through the thin Ruby launcher. Its YAML manifest contains an absolute plugin path;
after moving the prefix, reinstall with `cmake --install <build> --prefix <new-prefix>`
to refresh it. Release checks validate manifest-driven dispatch before moving and
after that refresh; library/CLI/package relocation is checked before reinstalling.

Public C++ source API compatibility is verified. Downstream C++ consumers should be
rebuilt; binary interchangeability with an already-installed C++ Fuel library is
not asserted. Validation covers Linux; Windows and macOS require their own runs.
Live service tests necessarily depend on their remote servers.

## Lifecycle hardening validation

Independent code, dependency/security and release reviews led to additional fixes
and deterministic regressions for literal multipart metadata, dependency and
redirect credential isolation, cached transitive dependencies, listing failures,
HTTP pagination metadata and exact legacy YAML output. Repeated Link fields,
quoted parameters and pagination completion are tested in both the native iterator
and CLI. Original upstream assertions and public headers remain unchanged.

The locked graph passes cargo-deny 0.20.2 advisory, license, bans and source checks,
with no advisory exceptions. The old unmaintained YAML implementation and affected
ZIP version were replaced. Duplicate transitive Windows dependency versions are a
reviewed warning, not a disabled vulnerability check. Documentation builds with
warnings denied, workflow syntax passes actionlint, and version tests reject stale
C++/CLI/Cargo/dispatcher strings.

Clean temporary Git snapshots pass the release-check script: verified crate,
source archive build with testing disabled and no upstream source checkout,
installation, relocated consumers and manifest-driven Ruby dispatch. Required
hosted CI repeats these checks against its exact checkout; no real package,
release or tag has been published.
